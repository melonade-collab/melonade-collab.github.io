Data Routing Explorer

A single business event can fan out to five different teams — each needing it in a different format, delivered to a different system, for a different reason. This explores that routing using a fictional retailer.

Problem

▼

A data PM's routing knowledge is almost entirely invisible. It lives in their head, in email threads, in undocumented assumptions: which teams need which events, why they need them, what format their systems actually ingest, and where the data lands. When that person leaves, it goes with them. This prototype makes that knowledge concrete and legible.

Tech

▼
  • Pure client-side JavaScript — no framework, no API dependencies
  • Three hardcoded scenarios (Order Placed, New Account Created, Out of Stock), each defining an event payload and a set of downstream consumers with routing metadata
  • Animated stagger on team rows when a new scenario loads

Features

▼
  • Three scenario tabs — switch between data events to see how each one routes differently across the same organisation
  • Each scenario shows the event payload fields and every downstream consumer with the reason they need it, the format they receive it in, and the destination system it lands in
  • Built around Fieldstone Co., a fictional mid-size e-commerce retailer with a realistic mix of SaaS tools (NetSuite, Klaviyo, Snowflake, Zendesk, Salesforce, LoyaltyLion) and custom internal systems

Why This

▼

This is what a data PM knows that most stakeholders don't see: not just that data needs to move, but who needs it, why, in what shape, and where. The gap between "we have this event" and "everyone who needs it is actually getting it in a usable form" is where data product management lives. This prototype shows that gap — and what closing it looks like.
